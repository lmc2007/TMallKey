FEATURES

为什么用它，而不是每次打开天猫校园

协议层的活儿一次做对，之后剩下的就是「点一下」。

完全离线

开锁不发起任何网络请求，飞行模式下可用。门锁本来就不联网，钥匙只在手机本地。

一次点击，亚秒级

冷启动首次约 1.2 秒，60 秒内再开约 0.4 秒。支持桌面快捷方式与快捷设置磁贴。

不碰原 App

不 hook、不注入、不读取天猫校园进程，只按抓到的报文逐字节复刻 BLE 协议。

凭证硬件级加密

activationKey 由 Android Keystore 的 AES-256-GCM 加密后落盘，密钥不可导出、随卸载销毁。

内置门锁仿真器

没有真机也能跑通完整开锁流程与协议回归，改动协议层有黄金向量兜底。

应用内更新

6 个加速镜像逐级回退，下载后校验 ZIP 魔数与 sha256，同签名直接覆盖安装。

GET STARTED

三步开门

唯一的门槛是「拿凭证」：需要让天猫校园自己开一次锁，把 activationKey 暴露在日志里。逐步操作见下方 完整使用教程。

STEP 01

拿凭证

两条路，任选其一：

  • 手机端：装 Shizuku 并激活，App 内「导入凭证 → 自动抓取」，然后去天猫校园门口开一次锁。
  • 电脑端：手机开 USB 调试连电脑，跑仓库里的 fktm/p0_capture.bat 抓 logcat。
STEP 02

导入

抓到后自动填入表单，确认保存即可。也可以手工填地址 + 32 位 activationKey，或直接粘贴电脑端导出的 credentials.json。

STEP 03

开锁

回首页点那个大按钮。首次会申请蓝牙权限，允许一次即可。之后就是「一点即开」。

完整使用教程

全程不需要 root。你需要的只有三样东西：一部 Android 手机、一扇你本人有权开启的门锁，以及一个能正常开锁的天猫校园 App。

Shizuku只有「方式一」需要，见下文
凭证是两样东西 —— ① activationKey：32 位十六进制，等价于这把锁的钥匙； ② 门锁的 BLE 地址：形如 AA:BB:CC:DD:EE:FF。

第 1 步 · 拿到凭证

钥匙是服务端按门下发的，只有天猫校园知道、也只会下发给它。所以要「拿」到钥匙，就得让它自己开一次锁，同时把过程记下来。三条路任选其一 —— 推荐方式三（补丁版），装完点一次开锁就完事。

最省事的路子：装一个「补丁版天猫校园」（本页下载区就有）， 登录后点一次开锁，TmallKey 就会自动把这把锁的凭证收进来。 全程不需要 Shizuku、不需要电脑、不需要 root。

① 安装补丁版天猫校园

到本页「下载安装」区下载「天猫校园 · LSPatch 补丁版」并安装。 它与官方版同包名、只能装一个：如果手机里已装官方版，需要先卸载 （登录态会重置，补丁版里重新登录一次即可，和平时登录一样）。

补丁版 = 官方 5.0.0 原包 + LSPatch 签名伪装 + 一个「凭证同步」小模块， 由发布流水线每次发版自动生成，与本页下载的永远是同一个文件。

② 登录并点一次开锁

  1. 打开补丁版天猫校园，用手机号 + 验证码登录（与官方版同一账号）；
  2. 进入门锁页，正常点一次「开锁」，等门真的打开。

③ 回到 TmallKey，门锁已在列表里

切到 TmallKey 的门锁页，新锁会自动出现在列表顶部 （默认名为「门锁 + MAC 尾号」，可在编辑里改名）。它的开锁方式与官方版抓到的凭证完全一致 —— 都是离线 BLE，一点即开，与天猫校园之后是否在线无关。

接水功能说明：TmallKey 内的「远程解锁水机」依赖服务端的校园用户档案， 该档案目前只在官方版长期登录的会话上存在；补丁版新登录的会话暂不支持 fkTM 内解锁水机 —— 接水直接用补丁版天猫校园即可（它自己解锁是正常的）。门锁开关不受影响。

不需要电脑。（ColorOS 16 中文语言下关闭了「禁止权限监控」，需要先把系统语言切成英文，不推荐）

① 装好 Shizuku 并让它运行起来

从 Shizuku 官网或 GitHub Releases 安装 Shizuku，再按你的设备情况启动它：

  • 无线调试（免 root，Android 11+）—— 推荐：打开「开发者选项」→「无线调试」→ 点「使用配对码配对设备」记下 6 位配对码，回到 Shizuku 点「通过无线调试启动」，按通知栏提示填入配对码。（不会打开开发者模式可以搜索教程）
  • Root—— 若设备已 root，直接在 Shizuku 里点「通过 root 启动」。

Shizuku 首页显示「正在运行」才算成功。重启手机后 Shizuku 会停止，需要重新启动一次。

② 在 TmallKey 里开始抓取

  1. 安装并打开 TmallKey；
  2. 点「+ 添加门锁凭证」，面板顶部就是「自动抓取钥匙站」；
  3. 点「开始抓取」；
  4. 第一次会弹出 Shizuku 授权框 —— 勾选「始终允许」并确定；
  5. 授权后再点一次「开始抓取」。

此时界面会显示「正在后台监听日志」，最长监听 4 分钟，命中会立刻结束。

③ 去开一次门

  1. 保持 TmallKey 在后台（别从最近任务里划掉它）；
  2. 切到天猫校园，走到门附近；
  3. 正常点一次「开锁」，等门真的打开。

④ 回到 TmallKey，保存

切回 TmallKey，表单会自动填入，确认后点「保存」。

抓取中切走时 App 会被系统冻结，这是正常的。TmallKey 在服务端做了「命中即落盘」—— 只要门开过一次，回到 App 就会立刻取回结果，界面短暂停在「抓取中」不用管。

适合没装 Shizuku、或手机端一直抓不到的情况。

① 准备

  1. 手机打开「开发者选项」→「USB 调试」；
  2. 电脑装好 platform-tools（即 adb）；
  3. 数据线连上电脑，执行 adb devices，手机上确认「允许 USB 调试」—— 能看到设备序列号即可。

② 开始抓取

下载仓库里的 fktm/p0_capture.bat，Windows 直接双击即可（它会自动清空日志缓冲、开始抓取，结束后自动跑校验）。其他平台手动执行下面两条：

下载 p0_capture.bat（推荐） GitHub 直连 gh-proxy 镜像 ghproxy.net 镜像 sakuramoe 镜像

推荐项是本页同源文件，点了直接下载；直连与镜像指向 GitHub 上的原始文件，部分浏览器会直接把脚本内容显示出来 —— 右键「另存为」保存即可。 

adb logcat -c
adb logcat -v time \
  VocLockHelperV2:V VocLockHelper:V VocLockJsBridge:V VocUnlockBridge:V \
  BluetoothHelper:V VocLockManager:V VocLockSession:V VocLockBridge:V \
  ZMUnlockBridge:V VocStatistics:V VocLogger:V Logger:V TLog:V \
  '*:S' > p0_capture.txt

③ 去开一次门

保持数据线连接（或用 adb tcpip 走无线），走到门口用天猫校园点一次开锁，等门打开。

④ 停止抓取，读出凭证

回到电脑按 Ctrl+C 停止抓取。此时 fktm/credentials.json 就是 TmallKey 可直接识别的 JSON，可以进入下一步。也可以手动跑一遍校验：

cd fktm
pip install pycryptodome
python cli.py verify --log p0_capture.txt

输出里直接就有你要的两项：

activationKey : 0123456789ABCDEF0123456789ABCDEF
macAddress    : AA:BB:CC:DD:EE:FF
日志里没打印 activationKey 也能拿到。密钥派生是可逆的 —— actualAesKey = randomNumber XOR activationKey，而 randomNumber（0D 响应明文）和 actualAesKey 日志里都有。 logparse.py 会自动反解，并且要求多组独立会话解出同一个值才采信，解不一致会拒绝下结论。

第 2 步 · 导入凭证

在 TmallKey 首页点「+ 添加门锁凭证」，有三种填法：

  • 手工填写—— 填「名称」（默认「宿舍门」）、「门锁地址」、activationKey，然后保存。地址必须是 AA:BB:CC:DD:EE:FF 格式，钥匙必须是 32 位十六进制。
  • 粘贴 JSON—— 直接粘贴 fktm/credentials.json 的整段内容，点「解析并导入」。同时支持带 locks 数组的完整结构和单个凭证对象两种形式：
{
  "locks": [
    {
      "name": "宿舍门",
      "address": "AA:BB:CC:DD:EE:FF",
      "activationKey": "0123456789ABCDEF0123456789ABCDEF"
    }
  ]
}
  • 自动抓取—— 见上面「方式一」，抓到后会自动填进表单，再点「保存」。

凭证保存在本机 Android Keystore 的加密区。

第 3 步 · 开锁

回到首页，点卡片中间那个大按钮即可。首次会申请蓝牙权限，允许一次即可。

  • 冷启动首次开锁约 1.2 秒，60 秒内再次开锁约 0.4 秒；
  • 页面底部的「收发时序」会逐条显示收发字节，方便确认每一步都通了；
  • 「查电量」按钮可以顺便读门锁电量。

连接不是常驻的，按两条计时规则自动回收 —— 进入前台先自动预连接，30 秒内没有开锁就断开；一旦开锁则保活 60 秒，期间再开锁会重新计时；退到后台（含息屏）立即让出。这是有意为之：把门锁的并发连接让给真正要用的人，下次开锁会自动重新连上。首页顶部的状态角标（● 已预连接 / ◌ 预连接中 / ○ 未连接）可以直接看到当前状态。

抓不到凭证？按这个顺序排查

先确认一件事：天猫校园这次开锁到底有没有成功？门必须真的开了才有日志可抓，先别急着怀疑 TmallKey。

方式一（手机）

现象检查
提示「Shizuku 未运行」Shizuku App 是否显示「正在运行」；重启手机后需要重新启动 Shizuku
停在「正在后台监听」不动是否已经点过「开始抓取」之后才去开的门（抓取会先清空日志缓冲）
一直抓不到天猫校园是否真的完成了开锁；地址是否填对；换电脑 adb 方式交叉验证
抓到钥匙但没地址日志里只有 key 没有 mac，手工填地址即可
长时间无结果4 分钟后会自动结束并给出诊断信息

诊断信息：

adb logcat -s fkTM:D                                  # App 侧抓取日志
adb shell cat /data/local/tmp/fktm_grab_diag.txt      # 服务端进度（需 shell/root）

方式二（电脑）

现象检查
adb devices 为空换线 / 换口；手机上确认「允许 USB 调试」弹窗
抓到的文件里没有 activationKey天猫校园必须先完成一次成功的开锁
有日志但没有钥匙行确认过滤标签里写了 VocLockHelperV2；天猫校园改版可能改了标签，先全量捞一次：adb logcat | findstr /i activationKey
verify 报缺少 pycryptodomepip install pycryptodome
都不行？换个时机再试一次。凭证抓取依赖天猫校园把日志打出来，不同版本、不同系统策略下差异很大 —— 但只要成功抓到过一次，之后就永久有效。
FAQ

常见问题

这和天猫校园是什么关系？会封号吗？

没有任何代码关系。它不调用天猫校园，也不读取它的进程，只是把 BLE 开锁报文按字节复刻了一遍。开锁时手机直接和门锁通信，服务器完全不知情。

「拿凭证」那一步只是趁天猫校园自己开锁时，从它自己打印的日志里把它已经下发给你的钥匙取出来 —— 钥匙本来就是你自己的。

换手机、重装系统之后还能用吗？

凭证存在本机 Keystore 加密区，不参与备份，卸载即销毁。换机请提前把 activationKey 抄下来（或在电脑端保留 credentials.json），在新机上重新导入即可。

为什么开锁不需要联网，但还是要蓝牙权限？

门锁是 BLE 蓝牙锁，手机就是通过蓝牙直接和它握手的。Android 12 及以上要「附近的设备」权限，12 以下要定位权限（系统限制，与 App 是否真的定位无关）。

为什么连上门锁之后过一会儿会自动断开？

这是有意为之。进入 App 会先自动预连接，30 秒内没有开锁就断开；一旦开锁则保活 60 秒，期间再开锁会重新计时；退到后台（含息屏）立即让出连接。

同一把锁可以被多台设备同时连，但并发会明显拖慢建连。让出连接是为了把门锁的并发让给真正要用的人，下次开锁会自动重新连上。

抓不到凭证怎么办？

先确认这次开锁真的成功了 —— 门真的开了才会有日志。手机端要注意 ColorOS 等系统会冻结后台进程，App 已经用前台服务 + 命中即落盘来兜底，但抓到后记得切回 App 让它读出来。

如果日志被 App 关掉了（比如官方升级后不再打印），就只能用 root + frida 那条备选路线了。

能开别人的门吗？

不能，也请不要尝试。activationKey 是服务端按门下发的，你只能拿到自己那扇门的。本项目仅供本人宿舍门使用。
